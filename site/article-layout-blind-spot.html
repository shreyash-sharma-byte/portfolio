The bug the layout check could not see

A nav label grew, the flex row wrapped, and the header bar doubled in height. The layout check passed 20/20, because a wrapped row is not overflow.

a check only sees the failure mode it was written for

The header is a flex row: the wordmark, then five nav links. I lengthened one nav label. That was the whole change, and it was enough to break the phone layout without breaking anything a machine was checking.

Measured at 390px: the nav's five links needed 252.3px and the box they were in was 234px. The wordmark took 108.6px of the same row. The nav row's default is flex-wrap: wrap, so instead of overflowing it wrapped to a second row, and the header bar grew from 65px to 109px. On an 844px-tall phone that is 44px of screen spent on a bar that had fitted on one line the day before.

The site has a layout check. It rendered every page at 390px and 1280px, compared documentElement.scrollWidth against the viewport, and listed every element whose right edge passed it. It reported 20/20 passing. It was right, and it was useless: a wrapped flex row is not overflow. Every box sits inside the viewport, the document is exactly 390px wide, and the only thing that changed was height, which the check never looks at.

That is the real lesson, and it is not really about flexbox. A check only sees the failure mode it was written for. This one was written for horizontal overflow, because that was the previous bug of this kind: a 784px column inside a 390px viewport. It cannot see a row that gives up and wraps, so as far as it was concerned nothing had happened.

The fix had two parts, and the second is the one worth copying. The layout fix restores the row: drop the surname from the wordmark at phone widths, which returns the 108.6px it was holding, and pin the nav to flex-wrap: nowrap so a row can never quietly become two. The check fix follows from that. With wrapping disabled, a future label that is too long has nowhere to go but sideways, and sideways is exactly what the existing check measures. The bar is back to 65px on one row, and the measurement that caused the incident is written into the stylesheet beside the rule, so the next person to change a label can see what the budget is.

What I did not do: add a check for header height. Pinning the row to one line makes the failure mode the failure the existing check already catches, which is a smaller change and the one that keeps working. A second checker nobody remembers to read is not a fix.
