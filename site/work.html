OpenClaimFlow

Implemented

An end-to-end insurance claims platform. Claimants file a loss online, the claim auto-routes to the least-loaded qualified adjuster, adjusters assess it through a staged workflow, and supervisors run the whole book with authority limits, audit and privacy controls.

23 tables · 62 HTTP endpoints · 30 migrations · 5 roles · 7 denial codes · Playwright across the full stack

The decision worth reading: authority is a gate, not a screen. A decision inside the adjuster's limit closes the claim and records a payment; above it the claim is re-assigned to the least-loaded L2 or escalated to a supervisor. Denials are never gated. Because the gate is one function called at decision time, the rule cannot drift between the interface and the server.

Angular 22 · Java 21 · Spring Boot · PostgreSQL 16 · Flyway V1–V30 · Keycloak · Playwright

Banking Microservices

Implemented

A retail and business banking platform across eight services: accounts, atomic money transfers, an event-driven payment pipeline, an immutable unified ledger, and role-based access behind an API gateway — fronted by an Angular client.

8 services · 5 databases · 3 Kafka topics · 76 tests · 9 architecture decision records

The decision worth reading: money moves without a race. Each transfer is one ACID transaction using a conditional update, so two concurrent transfers cannot overdraw an account — and the ledger entry is written to a transactional outbox in the same transaction, then moved PENDING → SENDING → PUBLISHED with confirmation and retry. No ledger entry is lost, and none is applied twice.

Java 17 · Spring Boot · Spring Cloud · Apache Kafka · PostgreSQL · Angular 22 · Docker

Enterprise Workflow Management System

Phase 1–2 implemented Phase 3 planned

A workflow platform where organisations define versioned templates, configure stations with role-based permissions, execute instances across those stations, and keep a complete history of every move.

9 realm roles · 11 data models · 4 task types · 5 validation gates per move

The decision worth reading: every station change passes one engine that runs five checks in order — the instance is active, the user holds the role required at the current station, the transition exists, all required tasks are complete, and the optimistic lock still holds. All five must pass before anything is committed.

Angular 17 · Django 4.2 · Django REST Framework · PostgreSQL 16 · Keycloak · Docker

Focused builds

Michiru — invoice automation

API complete Client not yet hosted

An invoice automation pair: a Spring Boot API that tracks every invoice through a real state machine and chases the overdue ones on a schedule, and an Angular dashboard that shows the invoices and the audit trail of every reminder sent.

10 endpoints · 17 tests · 3 entities · one reminder per invoice per three days

The decision worth reading: the reminder engine only chases invoices that are actually billable — status SENT, overdue or due soon — and a no-nagging rule allows at most one reminder per invoice per three days. Every reminder is a persisted record, so the audit trail is the product, not a log line.

Java 21 · Spring Boot 4.1.1 · Spring Data JPA · H2 · Angular 22 · TypeScript

Living Codebase Cartographer

Implemented MIT

An offline codebase mapper. Point it at any repository and it produces symbols, endpoints, call graphs, data lineage, blast-radius impact analysis and request-flow traces — then renders a portable explorer that opens straight from the filesystem. Python standard library only: no packages, no language server, no network calls.

Mapped 4 codebases · 606 files · 4,036 nodes · 12,333 edges · 428 checks passing

The decision worth reading: no fact is stated without its evidence. Every node and edge carries a confidence level, a file:line citation and the commit it was verified against, and that confidence is consumed downstream — an impact query prints each caller with its confidence, and the explorer draws and filters on it rather than decorating with it.

Python 3 (standard library only) · no dependencies · offline · MIT

ClaimShield AI

Working service Wider platform planned

A retrieval-augmented policy service. It indexes policy clauses into a vector store, retrieves and re-ranks the clauses behind a question, and answers only from what it retrieved — with citations and a confidence score — plus a local harness that scores the retriever itself.

93 indexed clauses · 29 evaluation questions · 5 endpoints · evaluation costs zero model calls

The decision worth reading: it refuses rather than guesses. Confidence is derived from retrieval distance, not self-reported by the model, and below a fixed floor the service returns "not enough evidence" without calling the model at all. The public console gives each address a small allowance of model calls, counted at the single choke point every call passes through.

Python · FastAPI · FAISS · sentence-transformers · Groq
