Emphasis from isolation, not from weight

Why this site ships no JavaScript, no build step and no web fonts — and the layout check that went on passing while the header was visibly broken.

the rules this site is built to, and what each one costs

A portfolio is an argument about how someone works, and it is made out of the same material as the work. The usual way to make that argument is to add: a hero animation, a web font, a component library, a scroll effect. The page ends up mostly about its own chrome. This site argues the other way round, and the rules below are load-bearing rather than decorative. Each one costs something, and the cost is the reason to trust it.

No JavaScript
One <script> element exists across all fourteen pages, and it is application/ld+json: structured metadata for a search engine, not behaviour. Nothing can fail at runtime on a page where nothing runs.
No build step
Hand-written HTML and a single stylesheet. There is no dependency to upgrade, no bundler to reconfigure, and nothing at all between an edit and the file that gets served.
No external requests
Type is the system font stack and every image is local. One origin, so there is no third-party request in the critical path, no flash of swapped type, and no visitor data leaving the page into somebody else's log.
Real pages, not one long scroll
Every page has one job. A URL per idea is linkable, and a page that is a single thing is a page somebody can finish.
One accent, used only where it means something
Emphasis comes from isolation and brevity, never from size or weight. A claim made loud is a claim that has to be, and if everything is loud then the one line that matters cannot be found.
A box around each section
A 1px rule is what separates "this is one thing" from "this is the next thing". It is the cheapest structure available, and it survives a 390px viewport.
Diagrams are text
The architecture diagrams are <pre> blocks held to a 48-column budget, and they scroll sideways rather than reflow — a diagram that wraps is no longer a diagram.
Nothing that needs explaining
No analytics, no cookie banner, no theme toggle, no newsletter. Each of those is a thing that can fail silently, or lie, or need a paragraph of apology.

The check that passed while the header was broken. Rules are worth nothing unless something tests them, so every page is measured at two widths — 390px and 1280px — and asserted to fit: fourteen pages, twenty-eight measurements, nothing extending past the viewport. That check found real bugs, and then missed an obvious one. A navigation label grew, the row of links wrapped onto a second line, and the header went from one line tall to two. All twenty-eight measurements passed.

The reason is that a wrapped flex row is not overflow. Everything still fits inside the page, so a measurement that asks "does anything stick out sideways" has nothing to report. The bug was plain in a screenshot and invisible to the test.

The fix was not a bigger test. It was to pin the navigation to a single line, so that the next label to grow overflows instead of wrapping — converting a failure mode the check could not see into one it can. That is the transferable part: when a test keeps passing on something you can see is wrong, the thing to change is often the page, not the test. Make the bad state representable, then it becomes detectable.

What it costs. A hand-written site is more editing than clicking. Fourteen pages is around 170 KB of HTML and one 27 KB stylesheet, served whole, with no framework in the middle of it. In exchange, every page is a single request that either arrives or does not: there is no state to hydrate, no hydration to fail, and nothing standing between a visitor and the work.

The same instinct runs through how these projects are hosted, where it shows up as one platform layer shared by every project instead of five duplicated stacks. Minimal is not a style here. It is the same decision — do not duplicate, do not decorate, do not require a runtime — applied to a stylesheet and to a server.
